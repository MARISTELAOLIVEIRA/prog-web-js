Módulo 7 de 8

Formulários e Validação

Ao final deste módulo, você será capaz de:

  • Montar um formulário em HTML, com <label>, <input> e botão;
  • Dar cara de site ao formulário com CSS;
  • Ler o que o usuário digitou e responder na própria página;
  • Usar os eventos submit e input;
  • Validar os dados e mostrar o erro na tela, com CSS e JavaScript trabalhando juntos.

1. Uma página, três camadas

Até aqui, o JavaScript morou no console. Agora ele vai para onde o usuário está: a página. E toda página de verdade tem três camadas, cada uma no seu trabalho:

HTML · estrutura

O que existe na página: títulos, campos, botões. É a placa com os componentes soldados.

CSS · aparência

Como cada coisa aparece: cor, tamanho, espaço. É o acabamento da placa.

JavaScript · comportamento

O que acontece quando o usuário age. É a corrente passando pelo circuito.

O arquivo completo: index.html

No VS Code, o projeto é uma pasta com três arquivos: index.html, estilo.css e script.js. Quem chama os outros dois é o HTML: 

<!DOCTYPE html>
<html lang="pt-br">
<head>
  <meta charset="UTF-8">
  <title>Meu primeiro formulário</title>
  <link rel="stylesheet" href="estilo.css">
</head>
<body>
  <form id="formCadastro">
    <label for="nome">Nome</label>
    <input id="nome" name="nome" type="text">

    <button type="submit">Cadastrar</button>
  </form>

  <script src="script.js"></script>
</body>
</html>
  • <!DOCTYPE html> avisa o navegador que a página é HTML moderno.
  • <head> é a parte que não aparece: o <meta charset> garante os acentos, o <title> é o nome na aba do navegador e o <link> chama o estilo.css.
  • <body> é tudo o que aparece na tela.
  • O <script> fica no fim do <body>: assim o script.js só roda depois que o HTML já existe.

Dentro do body: o formulário

  • <form> agrupa os campos e sabe ser enviado.
  • <label> é o texto do campo. O for="nome" liga o rótulo ao campo com id="nome": clicar no texto põe o cursor no campo, e o leitor de tela lê os dois juntos.
  • <input> é o campo. O type muda o jeito de digitar: text, email, number, password…
  • <button type="submit"> envia o formulário.

O editor abaixo funciona como o VS Code: cada aba é um arquivo da pasta do projeto. A página embaixo é o index.html aberto no navegador, e ela atualiza sozinha enquanto você digita.

Experimente: troque type="text" por type="password" e veja o que acontece. Depois, acrescente um campo E-mail, com o seu <label> e o seu <input>.

2. CSS: o formulário com cara de site

O HTML sozinho funciona, mas parece site de 1998. O CSS escolhe os elementos por seletores e diz como eles aparecem: 

label {          /* todos os labels */
  display: block;
  font-weight: bold;
}

.campo {         /* quem tem class="campo" */
  padding: 8px;
  border: 2px solid #c7cbe0;
  border-radius: 8px;
}

.campo:focus {   /* o campo com o cursor dentro */
  border-color: #2e7d5b;
  outline: 3px solid #b9e4cf;
}

.campo.erro {    /* o JavaScript liga esta classe quando der erro */
  border-color: #c22450;
}
Cada camada no seu trabalho: a classe .erro ainda não faz nada sozinha. Daqui a pouco o JavaScript liga e desliga essa classe, e o CSS cuida da cor.
Experimente: deixe o botão verde, mude a cor do campo com o cursor (:focus) e acrescente class="campo erro" no input do index.html para ver o vermelho. Por último, apague a linha do <link> no index.html: o visual some, porque o HTML parou de chamar o estilo.css.

3. Ler o campo e responder na página

Para conversar com o HTML, o JavaScript precisa achar o elemento. O document.querySelector() procura pelo seletor, igualzinho ao CSS: #nome é o elemento com id="nome". 

const campoNome = document.querySelector("#nome");
const mensagem = document.querySelector("#mensagem");

// .value: o texto que o usuário digitou no campo
// .textContent: o texto que aparece dentro do elemento
mensagem.textContent = "Olá, " + campoNome.value + "!";
Repare: nada de console. A resposta aparece na página, onde o usuário está olhando.
Experimente: mostre o nome em letras maiúsculas com .toUpperCase().

4. Eventos: submit e input

Evento é o aviso de que algo aconteceu na página. Dois deles são os melhores amigos do formulário:

  • submit: o formulário foi enviado (clique no botão ou Enter dentro de um campo).
  • input: o conteúdo do campo mudou. Dispara a cada letra digitada.
formulario.addEventListener("submit", function (evento) {
  evento.preventDefault(); // não deixa a página recarregar
  mensagem.textContent = "Recebido, " + campoNome.value + "!";
});

campoBio.addEventListener("input", function () {
  contador.textContent = campoBio.value.length + " de 80 letras";
});
Atenção: sem o preventDefault(), o navegador envia o formulário do jeito antigo e recarrega a página. A sua mensagem some antes de você ver. Teste: apague essa linha no script.js abaixo e envie.

5. Validar e mostrar o erro na tela

O usuário digita de tudo: espaço em branco, nome de uma letra, e-mail sem arroba. Antes de usar o dado, confira. Se der erro, o JavaScript escreve o aviso na página e liga a classe .erro; o CSS pinta o campo de vermelho. 

function validarNome(nome) {
  if (nome.trim() === "") {
    return "Escreva o seu nome.";
  }
  if (nome.trim().length < 3) {
    return "O nome precisa de pelo menos 3 letras.";
  }
  return ""; // texto vazio: sem erro
}
Dica: trim() tira os espaços do começo e do fim. Assim ninguém passa na validação digitando só espaço. E o aria-live="polite" no parágrafo da mensagem faz o leitor de tela anunciar o aviso assim que ele aparece.

6. Formulário completo: Cadastro de Alunos

Agora tudo junto, no projeto da disciplina. A regra é a do Sistema de Aprovação: média 6,0 e pelo menos 75% de frequência. Cada aluno cadastrado entra numa lista, na própria página.

Experimente: mostre embaixo da lista quantos alunos estão aprovados. O filter() do array turma resolve.

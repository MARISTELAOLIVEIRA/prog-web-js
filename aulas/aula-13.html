Passo 1 · parte 1

O painel em JavaScript puro

É o caso de uso da aula: os totais de aprovados e reprovados e a lista da turma. Lançou uma nota, o painel muda. Tudo com o que você já sabe: querySelector, createElement, classList e o submit da aula 12.

Repare na função atualizarPainel(): você é quem precisa lembrar de chamá-la toda vez que a turma muda. Num sistema grande, com dezenas de telas, esquecer uma chamada é um erro comum.

Faça assim:
  1. Crie a pasta aula13 no seu repositório, com index.html, estilo.css e script.js.
  2. Copie os três arquivos deste passo (botão ⧉ Copiar o arquivo em cada aba) e abra com o Live Server.
  3. Lance a nota de um aluno e veja os totais mudarem.
Teste:
  1. Apague a linha atualizarPainel(); de dentro do submit e lance uma nota. O aluno entrou na lista, mas o painel não mudou. Coloque a linha de volta.
Passo 2 · parte 1

O mesmo painel com Vue: o painel que se atualiza sozinho

Com o Vue, você descreve no HTML o que mostrar, e ele cuida de quando redesenhar. O JavaScript só guarda os dados (data), as contas (computed) e as ações (methods). Mudou a turma? O Vue redesenha sozinho, sem nenhum atualizarPainel().

O que é novo no HTML:
  1. {{ aprovados }} mostra um valor e se atualiza sozinho.
  2. v-model="nome" liga o campo à variável: digitou, a variável mudou.
  3. @submit.prevent="lancar" é o addEventListener("submit") com o preventDefault() já embutido.
  4. v-for="aluno in turma" repete o <li> para cada aluno, como o for...of.
  5. A linha <script src="https://unpkg.com/vue…"> traz o Vue da internet (CDN), sem instalar nada.
Faça assim:
  1. Na mesma pasta aula13, crie a pasta vue e copie para ela os três arquivos deste passo.
  2. Abra o vue/index.html com o Live Server (o computador precisa estar na internet, por causa do CDN).
  3. Lance uma nota: o painel muda igual ao do passo 1.

Apareceu {{ aprovados }} na página, em vez do número? O Vue não carregou: confira se o computador está na internet e se o endereço do <script src> do Vue está igual ao do passo.

Para o seminário (e o desafio extra):
  1. Compare os dois script.js: qual tem mais linhas? Em qual é mais fácil esquecer algo?
  2. O que o Vue acrescentou ao projeto (um arquivo de fora, uma sintaxe nova no HTML)? Para um painel pequeno, compensa? E para um sistema com 30 telas?
  3. O framework do seu grupo resolve o mesmo problema? Procure na documentação oficial como ele mostra uma lista e atualiza um valor.

Funcionou? git add . e git commit -m "Aula 13: painel em JS puro e com Vue".

Passo 3 · parte 2 · itens 6 e 7 da atividade

O repositório do grupo e as issues

Uma pessoa do grupo cria o repositório e convida as outras. Depois, cada tarefa do projeto vira uma issue: um cartão com o que fazer e quem faz.

Quem cria o repositório (uma pessoa só):
  1. No GitHub, clique em + › New repository.
  2. Dê o nome do projeto (sem espaços, por exemplo agenda-do-bairro), deixe Public (o GitHub Pages da aula 14 precisa) e marque Add a README file.
  3. Clique em Create repository.
  4. Vá em Settings › Collaborators › Add people e convide cada colega pelo usuário do GitHub.
Cada colega:
  1. Aceite o convite que chega por e-mail (ou em github.com/notifications).
  2. Clone o repositório no VS Code: Ctrl + Shift + P, digite Git: Clone, cole o endereço do repositório e escolha a pasta.
As issues (o grupo junto):
  1. Na aba Issues do repositório, clique em New issue.
  2. No título, a tarefa em poucas palavras ("Tela de cadastro"). Na descrição, o que precisa funcionar para a tarefa estar pronta.
  3. Em Assignees, escolha quem vai fazer. Clique em Submit new issue.
  4. Repita até cada tela do wireframe e cada parte do projeto ter a sua issue. Repare no número de cada uma (#1, #2…): ele vai ser usado no passo 4.
Passo 4 · parte 2 · item 8 da atividade

Cada um na sua branch, e o pull request

A branch é uma cópia do projeto só sua: você programa à vontade sem mexer no código dos colegas. Quando a tarefa fica pronta, o pull request pede para juntar o seu trabalho na branch principal (main), depois que um colega revisa.

Criar a sua branch (no VS Code):
  1. Clique no nome da branch, no canto de baixo à esquerda (está escrito main).
  2. Escolha Create new branch… e dê o nome da sua tarefa, sem espaços: tela-de-cadastro.
  3. Confira: o canto de baixo agora mostra tela-de-cadastro. Tudo o que você fizer fica nessa branch.
Programar e enviar:
  1. Programe a sua parte e salve.
  2. Na aba Source Control (o ícone de ramos, à esquerda), escreva a mensagem do commit e clique em Commit.
  3. Clique em Publish Branch para mandar a branch para o GitHub.

Prefere o terminal? São os comandos do conceito C3: git checkout -b tela-de-cadastro, git add ., git commit -m "Tela de cadastro" e git push origin tela-de-cadastro.

O pull request (no GitHub):
  1. Abra o repositório: aparece o aviso amarelo com o botão Compare & pull request. Clique nele.
  2. Na descrição, escreva o que você fez e closes #1 (o número da sua issue): quando o pull request entrar, a issue fecha sozinha.
  3. Em Reviewers, escolha um colega e clique em Create pull request.
  4. O colega abre a aba Files changed, confere o código e aprova. Depois, clique em Merge pull request e Confirm merge.
  5. De volta ao VS Code, volte para a main (canto de baixo) e clique em Sync Changes para trazer o trabalho de todo mundo.

Regra de ouro do grupo: ninguém programa direto na main. Cada tarefa, uma branch; cada branch, um pull request revisado por um colega.

O painel que se atualiza sozinho
